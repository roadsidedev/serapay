# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Primary users are people who want a simple, mobile-friendly way to use Ethereum stablecoins through a social sign-in experience. They need to see balances, move supported assets, use Sera Vault actions, explore mini apps, and manage their wallet without navigating a dense crypto interface.

## Product Purpose

Pocket Sera is a self-custodial Ethereum stablecoin wallet that organizes wallet balances, Sera Vault assets, trusted Sera actions, and mini apps in one focused product surface. Success means a user can understand their wallet state and complete common actions without relying on helper copy or technical guidance.

## Positioning

Pocket Sera combines social wallet onboarding with user-controlled Ethereum assets and a curated mini-app surface, while keeping Sera protocol actions close to the wallet experience.

## Operating Context

The product is used primarily on mobile web and also supports desktop web layouts. Users sign in with a connected social account, receive an embedded or linked Ethereum wallet, review balances and live Sera market data, perform wallet-approved actions, explore mini apps, and manage profile, security, and account preferences.

## Capabilities and Constraints

The product must preserve self-custody, explicit wallet approval for sensitive operations, Privy/social authentication, Ethereum Mainnet support, Sera API integration, per-user server-managed Sera credentials, live Sera market data, mini-app permissions, and mobile-first navigation. Protected Sera credentials remain server-side and encrypted. The interface should favor direct manipulation and clear hierarchy over explanatory helper text.

## Brand Commitments

The product name is Pocket Sera. The established visual accent is #7161DF, a deep purple/indigo. The interface should remain focused, calm, modern, and low-copy while retaining a polished glass-inspired surface language.

## Evidence on Hand

The existing implementation is the source of truth for wallet flows, Sera protocol integration, user profile preferences, mini-app workflows, authentication, and deployment configuration. No fabricated testimonials, customer claims, or performance claims should be introduced.

## Product Principles

1. Make wallet state immediately legible.
2. Keep sensitive actions explicit and user-approved.
3. Prefer intuitive controls over instructional copy.
4. Treat mobile as a first-class operating surface.
5. Keep user data and protocol credentials scoped to the correct account and wallet.

## Accessibility & Inclusion

The web interface should maintain keyboard access, visible focus states, readable contrast in both light and dark themes, semantic labels for icon-only controls, reduced-motion respect, and layouts that remain usable at narrow mobile widths.
